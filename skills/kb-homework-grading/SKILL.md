# 作业照片 → 转录 → 批改 → 卡片

> 适用：英语语法填空、数学解答题、语文阅读、理化题目、老师发的讲义……凡是"照片 + 要求整理/批改"的场景。
> 命令都在**知识库根目录**执行；不要给原生命令加管道或重定向（受限沙箱会拦，`> $null` 会让命令**根本不执行**）。

## 0. 全流程（七步）

```
① 照片留档 → ② 转录原件 → ③ 批改（digests/）→ ④ 登记 scan
→ ⑤ 建卡 notes/ → ⑥ link-notes / build-index / obsidian-sync → ⑦ 体检
```

## 1. 照片留档（**先做，否则后面无法回溯**）

附件通常在 agent 的临时目录，**没有扩展名**，必须复制进知识库并改好名字：

```
<知识库>/inbox/照片-<学科>/图N-<主题>.jpg
```

规则：一个来源一个子目录（`照片-英语/`、`照片-数学/`）；命名带**图序 + 主题**，便于卡片回引。
照片是**原件**：只复制、不改动、不裁剪覆盖（要裁剪就在临时目录做，别写回库）。

## 2. 转录为"录入原件"

写成 `<知识库>/inbox/<学科>-<主题>.md`。**照抄，不意译、不补充原文没有的内容**；印刷体的表格要保留表格结构。

必须做到：

- **首行加 front matter**（`---` … `---`）：不然后续脚本行为不可预测。
  例：`kb_inbox: true` / `title` / `source_type: 手工录入（照片转录）` / `entered: YYYY-MM-DD`
- **讲义/试卷/规则类**文件（不是词表）在文件开头加一行跳过标记：
  `<!-- kb:no-vocab ：本文件是讲义转录，不是词表，请 extract-vocab 跳过 -->`
  （`extract-vocab` 会用「第二个 `---`」判断 front matter 结束，正文里只要出现一条 `---` 分隔线，讲义就会被当成词表扫出垃圾词条。）
- **手写内容**一律写成 `【手写：xxx】`；读不准标 `[?]`；**读不出就写「无法辨认」，绝不猜**。
- 结尾加一节 **「待确认项」**，把照片本身的缺陷写清楚（跨页、编号错位、缺答案页、字迹被裁切…）。

## 3. 批改（写成 `digests/<主题>-批改.md`）

逐题表格，列为：`题号 | 语境/题干 | 正确答案 | 你的作答 | 判定 | 错因/知识点`

- 判定**只用** `✓` / `✗` / `待确认` 三种。
- **正确答案必须给语法/知识理由**，不能只给答案。
- **没有官方答案页时必须显式声明**：「表中答案是依据规则推出的，若与老师答案不同以老师答案为准」。
- 最后加「考点小结」+「失分集中点（2~3 处）」。
- 判错要具体到**规则**（例：目的状语用 to do，不用现在分词），不要只写"错了"。

## 4~6. 登记 → 建卡 → 同步

```bash
node tools/scan.mjs --root=inbox        # 取回新 id（kb-XXXX）
# 写 notes/kb-XXXX-<slug>.md（见下）
node tools/link-notes.mjs               # 校验卡片 + 回填 source/sha256
node tools/build-index.mjs
node tools/obsidian-sync.mjs            # 刷新首页（会把 digests/ 的成品也挂上）
```

**卡片规范**（`link-notes.mjs` 会校验，违反就报错）：

- front matter 必填：`id/title/source/source_type/tags/status/created/updated/sha256/summary/key_points`
  - `source` 写录入原件的绝对路径；`sha256` 可留空（脚本回填）；**`source` 不能漏，脚本只纠正不新增**。
- `key_points` **3~7 条**（超了会报错，合并两条即可）。
- 正文 **≤600 字**（长文档 ≤1600 字）；正文写「可判定的几处 + 下一步怎么用 + 关联」。
- `tags` **只能用 `index/tags.md` 里的**；缺标签就先往词表追加定义（一次最多 3 个），再用。
  常用：学科（`语文`/`数学`/`英语`）+ 类型（`试卷`/`讲评`/`教材`/`作文`）+ 主题（`语法`/`词汇`/`文言文`）。
- `created` / `updated` 写**今天日期**；用户要求"标明日期"时，正文里也点一句。
- 链接写**完整文件名 + 显示文本**：`[[kb-0533-英语-语法填空两篇批改|kb-0533]]`；**绝不只写 `[[kb-0533]]`**（会生成空笔记抢走别名解析）。

## 7. 体检（每次改完必跑）

```bash
node tools/obsidian-check.mjs   # 同名 / 断链 / alias / 空笔记
node tools/check-yaml.mjs       # front matter 语法
```

## 8. 老实话汇报（用户最在意这点）

汇报时必须写清三件事：
1. **能判定几处、待确认几处**（别把"待确认"混进"对了"里）；
2. **答案的来源**（官方答案页 / 按规则推定）；
3. **照片本身的缺陷**（跨页、编号错位、缺页、字迹不清）。

**宁可少判，不可错判。** 读不清一律「待确认」——这条比"多批几题"重要得多。

## 9. 多图批次用子代理（省上下文）

- 每个子代理给 **1~5 张图** + 明确输出文件路径，**要求它只写文件、不跑脚本**，回报限制在 8 行内。
- prompt 里必须写死：**禁臆造、手写标 `【手写：】`、读不清标 `[?]`、结尾列「待确认项」**。
- 子代理交回来的文件，**必须自己核一遍**（抽样读批改表，用你的学科判断检查它对不对）——它是助手，不是权威。
- 子代理容易犯的错：① 忘加 front matter（→ 加跳过标记更稳）；② 在文件里写 `---` 分隔线（→ 触发词表误扫）；③ 把标题层级写乱（`## 注：…` 这种）。

## 10. 常见坑速查

| 现象 | 原因 / 处理 |
| --- | --- |
| 词条数莫名增加 | 讲义被 `extract-vocab` 扫了 → 加 `<!-- kb:no-vocab -->` |
| 卡片报"缺少必填字段 source" | `link-notes` 只纠正不新增 → 手工补上 source |
| 卡片报"key_points 超过 7 条" | 合并两条最相关的 |
| 附件路径无扩展名、复制后打不开 | 复制时显式命名成 `.jpg` |
| 手写读不准却想"猜一个" | **不许猜**，写「待确认」 |
| 在 PowerShell 里写内联 node 正则 | 会被引号/`$` 转义搞坏 → **写成脚本文件**再跑 |
