# 先同步知识库，再详细讲解

## 默认范围与入口

- 当前知识库根目录为 `<知识库根目录>`；命令在该目录执行，先读其 `AGENTS.md`。
- 在已建立的知识库作业/学习上下文中，默认把新讲解和追问答复同步后再发送详细聊天答复。用户当次明确要求只聊天、只读或不保存时，以该要求为准。
- “同步所有知识库”默认指当前项目相关的记录与派生层：原件关联、`digests/` 详解、`notes/` 摘要卡、catalog、总索引、首页和适用的学科汇总。若用户明确指定多个库，逐库按其规则同步并分别报告；不要凭此措辞扫描其他未指定库或进行云端、Anki及其他外部服务同步。
- 照片作业同时按 `kb-homework-grading` 留档与转录；维护流程参考 `kb-longterm-ops`。不重复执行已经完成的照片留档或建卡。

## 每次讲解的顺序

1. 根据题号、讲次、照片页码及最近对话，定位原件、现有批改、摘要卡。题号冲突时先根据上下文区分。
2. 先完成推导与复核。区分题干原文、学生作答、AI推导与核验结论；缺失条件或不清字迹不猜。
3. 将即将在聊天中给出的完整解释写入对应 `digests/`，包含题意、目标结构、每一步等式、所用规则、为什么这样变形、合法性条件、结果与易错点。
4. 后续追问在同题详解中补充用户卡住的具体步骤和说明；保留已有正确内容，避免每次复制出新的重复题目。发现旧解释错误时明确订正并更新摘要卡，不能仅在聊天里纠正。
5. 更新关联摘要卡的要点和详解链接，保持短卡规范，长推导放在 `digests/`。原件、照片与 `inbox/` 转录保持不变；改现有加工文件前备份。
6. 完成下列同步和验证后，才发送详细教学答复。中途可以简短报告进展。

## 同步与验证

仅有讲解更新时，不需要重扫所有磁盘原件。新增录入原件时才运行 `node tools/scan.mjs --root=inbox` 取得id。

按依赖顺序执行：

```powershell
node tools/link-notes.mjs
node tools/build-index.mjs
node tools/obsidian-sync.mjs
node tools/obsidian-check.mjs
node tools/check-yaml.mjs --all
node tools/check-math.mjs --quiet
```

- 新增学科卡片或改变汇总字段/分类时，按需刷新对应学科汇总；仅细化同题步骤时更新既有详解入口即可。
- 相关层不存在或与本次内容无关时，不为了“全同步”重建词库、素材库或复习卡。不得手改脚本维护的catalog、全文缓存及派生目录。
- 检查实际输出，不把退出码0等同于所有质检通过；区分本次新增问题与已存在的原文层问题。
- 备份存为 `.bak` 或压缩包，避免备份里的同名 `.md` 参与Obsidian索引。
- 同步失败时保留已完成内容，修复当前可解决的问题；最终准确说明完成和未完成的层，不声称全库已同步成功。

## 聊天教学风格

- 简短说明同步结果，并链接对应详解，然后直接回答用户本次问题。
- 默认详细讲解，粒度参照“展开平方→逐项相加→按共同因子分组→代入恒等式”。不要只写答案或将多个关键变形压在一行。
- 展开括号时列出全部项；移项时交代符号变化；约分/除法时说明非零条件；用公式时写出公式及其在本题的对应关系。
- 先说明变形为什么有用，再给推导；区分“数学成立”与“学生已经作答正确”。没有新作答证据，补充教学不改变原批改判定。
- 用户继续追问时，重新执行“解答复核→保存补充→同步验证→聊天解释”，只细讲他提出的卡点，除非他要求重讲整题。
