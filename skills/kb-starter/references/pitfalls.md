# 从零构建知识库：已知的坑与解法

> 本 skill 记录的是**实际踩过的坑**，不是理论。每条都给了可识别的症状和可直接执行的修法。

## 0. 先定四条架构决策（决定后面 80% 的麻烦）

1. **库放在 Agent 的会话工作区内**（如 `D:\工作区\知识库`）。放在工作区外，每次写入都要提权批准，跑到第 20 个文件时你会崩溃。
2. **只登记路径，不复制原件**。原件永远只读；知识库保存"路径 + 指纹(sha256) + 摘要"。
3. **三层权威**：`原件 > 摘要卡 > 派生索引`。冲突时以原件为准，并立刻修正卡片。
4. **搬运而非重写**：抽取类产物（素材、词条）必须是原文**逐字片段**，脚本只负责切分和贴标签。一旦让模型"总结成素材库"，就再也分不清哪句是原文、哪句是二手生成。

## 1. 环境类困难（沙箱 / Windows）

### 1.1 原生程序不能接管道 → `Access is denied`
**症状**：`node x.mjs | Out-String`、`node x.mjs | Select-Object -First 3`、甚至 `node x.mjs > $null` 都报 `Access is denied`；但直接跑 `node x.mjs` 正常。
**根因**：沙箱禁止给原生程序创建管道（命名管道受限）。PowerShell 的 `|` 与 `>` 都会为原生程序建管道。
**修法**：命令**裸跑**，不要管道、不要重定向。要截取输出就写进脚本自己 `fs.writeFileSync`。
**坑中坑**：`> $null` 看起来只是丢弃输出，但它会让整条命令**不执行**，而你只看到后续步骤的数字不对（例如"卡片数只有 129"而实际有 172）。

### 1.2 Windows PowerShell 5.1 的 `-Encoding UTF8` 写 BOM，毁掉 front matter
**症状**：Obsidian 属性面板异常、脚本的 `^---` 匹配失败；文件头出现 `EF BB BF`。
**修法**：改文本文件一律用 `write`/`edit` 工具或 Node 脚本；必须用 PowerShell 时：
`[System.IO.File]::WriteAllText($p,$t,(New-Object System.Text.UTF8Encoding($false)))`

### 1.3 中文路径不要从控制台输出里重打
**症状**：`Test-Path` 对明明存在的路径返回 false。
**根因**：控制台回显的编码/不可见字符与真实路径不同。
**修法**：用 `$_.FullName`、`Join-Path` 传对象，绝不手抄中文路径。

### 1.4 内联 `node -e` 在 PowerShell 里会被引号/转义搞坏
**症状**：脚本报 `Unexpected token`、正则里的 `$` 变成字面量导致"全部报错"（曾出现 187 个文件全报错、2429 处假问题）。
**修法**：超过两行的逻辑一律**写成文件**再跑（`tools/xxx.mjs`）。一次性脚本也不例外。

### 1.5 网络：`api.github.com` 可能 403，但 raw / releases 直链可用
**修法**：优先 `https://raw.githubusercontent.com/<owner>/<repo>/<branch>/<file>` 与 `https://github.com/<owner>/<repo>/releases/latest/download/<asset>`；用 Node 的内置 `fetch`（本机 Node 24）。
**注意**：`pwsh` 的 `Invoke-WebRequest` 可能 TLS 握手失败，改用 Node。

## 2. Obsidian 兼容类困难

### 2.1 文件名必须全库唯一
**症状**：`[[X]]` 解析到错误的文件。
**修法**：生成器给文件加稳定前缀（`kb-0042-`、`2026-05-10-`）；建个体检脚本检测同名。

### 2.2 别名解析不可靠 —— 点一下就能"污染"你的库
**症状**：点击未解析的 `[[kb-0015]]`，Obsidian 在**库根新建一个 0 字节空笔记** `kb-0015.md`，反过来抢走同 id 别名的解析，于是真卡片再也点不到。
**修法**：
- 关联一律写 `[[完整文件名|显示文本]]`，**不要只写 id**；
- 写个归一化脚本批量修（`fix-id-links.mjs`），并在体检脚本里把它列为**错误**（不是提示）；
- 定期清理库根的 0 字节文件。

### 2.3 front matter（属性面板）不渲染 Markdown，也不渲染数学
**症状**：`summary: "**加粗**"` 在属性面板里显示成带星号的原文；`key_points` 里的 `$x^2$` 永远显示源码。
**修法**：属性面板只当"权威文本"用；**要给人看的渲染内容放进正文**。数学卡可以自动生成一个「公式速览」小节，把属性里的公式搬进正文（属性保持不动）。

### 2.4 数学公式：位置 + 定界符 + 表格三重坑
- **位置**：只有正文渲染；front matter、行内代码、代码块、Bases 视图、搜索面板都不渲染。
- **定界符**：`$…$`、`$$…$$`、`\(…\)`、`\[…\]` 都行；但**行内公式不能跨行**（整段写一行），跨行用 `$$…$$`。
- **表格**：单元格里的裸 `|` 会被当分隔符 → 绝对值写 `\lvert x \rvert`。
- **奇数个 `$`**：会让后面半段中文被吞进数学。写个体检脚本扫"每行 `$` 是否为偶数"。

### 2.5 `.base`（Bases）语法不稳，别当唯一入口
**修法**：视图文件 + **一份静态 Markdown 总表**双保险；总表用 Markdown 链接（`[标题](notes/x.md)`），避免表格里转义 `|` 的麻烦。

### 2.6 `fulltext/` 这类"给搜索用的副本"要单独一层
Obsidian 只索引 Markdown：PDF/Word 的正文要落到 `.md` 才能被搜到。

## 3. 文本抽取类困难

### 3.1 PDF 无文本层 → 标 `needs-ocr`，不要凭文件名编造
**修法**：抽取结果为 0 字时置状态 `needs-ocr`，卡片照写但明确写"内容不可用"。Windows 自带 `Windows.Data.Pdf` + `Windows.Media.Ocr` 是可行且零依赖的 OCR 路线。

### 3.2 乱码的"假成功"
**症状**：日志说"抽出 4872 字"，但正文 0 个汉字（字体缺 ToUnicode 映射）。
**修法**：抽取后统计 CJK 字符占比，低于阈值（如 0.5）判定失败 → `needs-ocr`。

### 3.3 PDF 表格必然丢结构
**修法**：卡片里显式标注「表格需回原件核对」，不要用散文复述表格数字。

### 3.4 用 Word COM 打开 PDF 会挂
**修法**：纯 JS 方案（pdfjs 系）优于 COM 自动化；COM 只用于真正的 .doc/.docx。

## 4. 生成器/脚本类困难（最隐蔽，必须逐条防）

### 4.1 字段名被当成条目标题
**症状**：切分出的条目叫「素材内容：」「适用主题：」。
**根因**："粗体行 = 条目"的正则没要求**以数字/序号开头**。
**修法**：`^\*\*\s*(?:\d+|[一二三四五六七八九十]+)\s*[.、)）]?\s*[^*]{2,60}\*\*\s*$`

### 4.2 单条目小节被合并
**症状**：某个小节只有一条却被并进小节名。
**根因**：切分阈值写成"≥2 个粗体项才切"。
**修法**：`>= 1`。

### 4.3 漏 `return` 导致同一行既归位又进异常报告
**症状**：既生成了条目，又出现在"未识别清单"里（数量对不上）。
**修法**：每个分支处理完就 `return`；用两份计数（收录数 + 未识别数 = 候选数）自查。

### 4.4 "清空派生层"会误删别的脚本产物
**症状**：重跑 A 脚本后，B 脚本生成的总表消失了。
**修法**：清空时排除非自己生成的文件（`if (f !== '素材库总表.md') rm(...)`），或把产物分目录。

### 4.5 增量导出会覆盖清单
**症状**：分批导入后 manifest 只剩最后一批。
**修法**：manifest **按 id 合并**写入；或者干脆让下游直接读 catalog（累积的）而不是 manifest。

### 4.6 批量归一化会误伤同前缀文件
**症状**：把 `kb-0442-01-屈原` 当成 `kb-0442` 的卡片引用，改出一堆错链接。
**修法**：排除 `^kb-\d{4}-\d{2}-` 这类"条目文件名"模式；改完**立刻重建**受影响的产物。

### 4.7 体检脚本的三类假阳性（会淹没真问题）
- Windows 路径里的 `\(`（`D:\资料\(2020年…)`）被当成公式定界符 → 先 `stripPaths`
- 说明文档里解释 `$` 的散文（反引号内）→ 先 `stripInlineCode`
- 只读层（对话原文/镜像）的问题 → 单独统计，不列为待修

### 4.8 别把 A 层的字段规范套到 B 层
**症状**：对派生层报 251 个"缺少必填字段"。
**修法**：按目录作用域校验（只有卡片层校验卡片字段）。

## 5. 子代理（subagent）协作类困难

### 5.1 标签漂移
子代理会自己发明标签。**修法**：prompt 里给**受控词表**并注明"只能用这些"；事后用脚本校验。

### 5.2 用 catalog 标题当文件名 → 断链
**症状**：子代理写 `[[kb-0505-2026-08-19-第七题提示]]`，但实际文件名不含日期。
**修法**：给子代理的模板里要求"链接目标 = 实际文件名 + 别名"，并提供归一化脚本兜底。

### 5.3 正文超长
**修法**：卡片长度用脚本校验；若某个自动小节（如「公式速览」）属于渲染辅助，**统计长度时排除它**。

### 5.4 并发写同一目录
**修法**：子代理只写 `notes/`；一切 `index/`、`cache/`、派生层由主控脚本统一跑。

## 6. 流程类（最有价值的三条）

### 6.1 先小样，再全量
实测：3 个样本一次就抓到 2 个解析误判。全量跑的话，几百条产物全部被污染，返工成本是 10 倍。

### 6.2 先写验收器，再写生成器
每个生成器都配一个只读体检脚本（YAML / 公式 / 链接 / docx 结构）。**验收器是唯一能证明"产物可用"的东西**，不要靠肉眼抽查。

### 6.3 透明度 > 自动化
- 抽取产物带 `conf: high/medium/low` 分级；
- 每条带 `anchor: L120-L135` 行号，可一键回原文；
- 建一份「未收录清单」，把没搬进来的东西逐条列出 —— **"漏"必须可见，不能静默丢弃**。

## 7. 建库标准顺序（每步都要验收）

```
登记(scan) → 抽正文(extract) → 写卡片(notes) → 校验回填(link-notes)
→ 建索引(build-index) → 同步到 Obsidian(sync + fulltext)
→ 派生素材/词条/复习卡 → 体检(check-yaml / check-math / obsidian-check)
```

## 8. 一句话原则

**宁可漏、不可错；可见 > 静默；先小样、后全量；搬运优于重写；派生层可重建，用户资产（复习进度、手写卡片）绝不可覆盖。**
